# EchoForge 0.9.7

**The words arrive while you are still speaking.** Until now a dictation was
decoded whole, after the key went up: a ten-second sentence was ten seconds of
silence and then a wait. This build decodes each phrase as soon as you finish
saying it, while the microphone is still open - the words grow along the
capsule as you talk, and when you stop, only the last phrase is left to decode,
so the paste lands almost immediately. It is **on by default**, and your
recordings, personal terms, snippets, styles, shortcuts and downloaded models
are untouched by this update.

> The download is still `EchoForge.dmg` and it still installs `EchoForge.app`.
> The app introduces itself as Kongweh once it starts. That split is deliberate -
> see "One app, two names" in the 0.9.1 notes.

## Live transcription

Nothing to set up: it is on. What you notice is the capsule showing the words
committed so far while you speak, and the transcript arriving almost as soon as
you stop.

Three things never change, and they are the design rather than its limits:

- **Nothing is pasted early.** The text still reaches your document once, at
  the end, after every stage it always went through - script normalisation,
  your personal terms, spoken corrections, style rewriting. The words on the
  capsule are a view of the decode, not an early delivery of it, and the line
  only ever grows: it never revises itself in front of you.
- **If anything on the live path fails, you never find out.** A microphone
  that will not share its stream, an utterance that will not decode, an engine
  changed mid-sentence - each one falls back to transcribing the whole
  recording exactly as before, and the recording is still written and kept the
  whole time.
- **Nothing new leaves your Mac.** The extra decode goes to the local engine
  you already selected. On the cloud engine nothing changes at all: it stays at
  one request per dictation.

Two subtler improvements travel with it. On **Automatic** language, Whisper
used to detect the language again for every phrase - about half a second each -
and could in principle decide differently mid-sentence; the language is now
detected once, on the first phrase, and held for the rest of the dictation. And
each engine's phrases are cut at a length measured against that engine, so a
phrase is never split where the recognizer would lose words.

Only the dictation key dictates live. ⌥A, ⌥S, ⌥E and ⌥Y are unchanged, and so
are dropped files, History re-transcription and `echoforge transcribe`.

**Settings → Shortcuts → Recording Behavior → Live transcription** is the
switch, beside the capsule's own. Turning it off restores the whole-file decode
exactly - and if you had already turned it off before this update, it stays
off: the default only fills in for a switch nobody has touched.
[docs/live-dictation.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/live-dictation.md)
is the whole story.

## Everything unchanged from 0.9.6

- **The cloud path is still opt-in and still off**, and live transcription does
  not weaken it: the cloud engine is never given a live session, so a dictation
  to your own provider is still exactly one request. Two features can be
  pointed at an OpenAI-compatible provider, speech transcription and the spoken
  "Translate to …" command, and switching either takes an explicit acceptance
  of a sheet naming what is uploaded and where. Style rewriting, Fix with AI,
  voice edit (⌥E), the Ask panel (⌥A), screen questions (⌥S), channel-name
  matching and app vocabulary have no cloud path at all, enforced in code. A
  0.9.7 install you never point at a provider sends nothing, anywhere, with the
  single exception of the YouTube command if you add a channel and use it: that
  request carries a channel id you typed and nothing about you.
  [docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).
  If you need "not present" rather than "not enabled",
  `Scripts/build_release.sh --offline-only` still builds exactly that; it is not
  published as a separate download here.
- **Every shortcut is where it was.** ⌥` records, ⌥A opens Ask *and listens*,
  ⌥S asks about the screen, ⌥E edits highlighted text, ⌘F focuses history
  search, ⌥M switches engine, ⌥Y runs the YouTube command - all rebindable in
  **Settings → Shortcuts**. Pausing from the menu bar stands them all down at
  once and is forgotten when you quit.
- **History still says what each entry was** - Dictation, Ask, Voice edit, File
  transcription, YouTube command - and entries from before 0.9.1 are still
  labelled "Older recording" and never relabelled. Search (⌘F) and **Export
  transcript** are unchanged, still entirely local, and an exported file still
  carries no row id, audio file name or source path.
- **The app is still thin.** It ships no model weights. The model you choose is
  fetched on demand and checksummed, SenseVoiceSmall as a verified model pack
  and every other engine by its own downloader, and lands in Application
  Support, where it survives replacing the app. This build does not change the
  SenseVoiceSmall pack, so an engine you have already downloaded is not fetched
  again.
  [docs/model-packs.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/model-packs.md).
- **Kongweh still never checks for updates on its own.** Checking, downloading
  and installing are three separate things you press, and an update is only
  ever downloaded from this repository's own GitHub releases.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try, typically "the app is damaged
and can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Download `EchoForge.dmg`. Its SHA-256 is published beside it as
   `EchoForge.dmg.sha256`, and `shasum -a 256 EchoForge.dmg` is how you check
   it.
2. Open the disk image and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
3. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in
     Terminal (adjust the path if you installed it elsewhere).

The app in Finder is still `EchoForge.app`; it introduces itself as Kongweh
once it starts.

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording**
the first time you use ⌥S. **This is expected and is not a regression**; it
happens on every unsigned update and will keep happening until these builds are
signed with a Developer ID.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add
the new app back; macOS otherwise keeps showing the old entry as granted while
the new build has nothing. The new entry may appear under either name.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks whether it
may use information stored in your keychain. Choose **Always Allow** and it
stops asking. An install that has never turned the cloud path on never reads
the Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).

## How this build was made

Produced by `Scripts/build_release.sh` and published only after
`Scripts/verify_release_package.sh` checked every embedded library's signature
and `@rpath` dependency and **started the app**.
