# EchoForge 0.9.2

**One user-visible change: a ⌥Y command that mishears a channel name now offers
your own list of channels and lets you pick one with the keyboard, instead of
refusing and leaving you nowhere to go.** Nothing about recognition, transcripts,
styles, storage or the security model changes in this build, and your
recordings, personal terms, snippets, styles, shortcuts and downloaded models are
untouched by this update.

> The download is still `EchoForge.dmg` and it still installs `EchoForge.app`.
> The app introduces itself as Kongweh once it starts. That split is deliberate -
> see "One app, two names" in the 0.9.1 notes.

## A misheard channel name now offers your list

Hold **⌥Y**, say a channel's name, let go, and that channel's newest video opens
in a new Chrome tab. That has worked since 0.8.4 - as long as the speech engine
wrote the name the way you stored it.

When it did not, there was nowhere to go. A channel stored as `valley101` is
matched with case and spacing ignored, so "Valley 101" reaches it - but an engine
that wrote **"Vali101"** produced a two-second **"Channel not in your list"** and
that was the end of the press.

**Now your own channels appear.** Kongweh shows what it heard, lists the channels
you added with the closest spelling first, and waits for you:

- **↑ / ↓** move through the list, wrapping around at either end
- **type** to narrow it - part of a name, ignoring case and spacing
- **Return** (or the keypad's Enter) opens the highlighted channel's newest video
- **Escape** closes the panel and opens nothing

The closest-spelling row starts highlighted and is badged as a suggestion, so the
common case is one keystroke. While an input method is composing, every one of
those keys belongs to the input method instead - this app's users type Chinese.

Both halves are written into History: the picker going up, and then either the
video that opened - recorded as a channel you chose yourself - or that you closed
it without choosing.

If you would rather a command that misses simply say so, as it did before, turn
off **"Let me pick from my channels when a name is not recognised"** in
**Settings → Dictionary & Snippets → YouTube Channels**. That switch is **on by
default**, and turning it off restores the previous refusal exactly. The way to
stop being asked at all is unchanged and takes one paste: copy the spelling out
of the History entry and add it as a **spoken name** on the channel you meant.

### Choosing is not a looser match

**The allowlist is still the whole security model, and it is unchanged.** Nothing
about how a spoken name is matched has been widened: it still has to equal one
channel you stored, in full, through the same two deterministic tiers - the
stored spelling, then the same comparison with internal spaces folded away - with
ambiguity detected in each tier separately and separately refused. "Vali101"
still matches nothing on its own, and that refusal is deliberate: a near miss
that opened *something* would be the app choosing a channel you did not.

What the picker adds is a **keystroke of yours**, and it can only ever produce a
channel you configured:

- the list holds the configured, enabled channels **that this press resolved
  against**, carried rather than re-read, so a Settings edit made while the panel
  is up cannot widen what one press can reach. There is no search, no place to
  type a channel that is not yours, and nothing that turns typing into an
  address;
- the closest-spelling ordering is a **hint beside a row you still have to
  choose**. It compares only the names and aliases you typed into Settings -
  never a channel id, a URL or a host - and it cannot open anything. Rows below
  the suggestion threshold keep your own list order;
- nothing is opened until you press Return, the choice is re-checked against that
  same list before anything opens, and Escape opens nothing at all;
- with no channels stored, no picker appears - the command says there is nothing
  in your list yet and where to add the first one;
- a press with nothing heard opens no panel either, so a stray ⌥Y never
  interrupts you.

A channel is still named only by the canonical `UC…` id you paste into Settings
yourself: nothing resolves a `@handle`, nothing searches YouTube, and no spoken
words are turned into an address.

### Your dictation shortcut is still text and only text

Unchanged: the router that reads dictations has no case that opens anything, so
**no wording of a dictation can reach a browser or raise this picker**. Saying
"open YouTube channel Valley 101" into your dictation key **types those words**.
What ⌥Y captured is still read only as a channel name - it never reaches style
rewriting, the Ask panel, the snippet expander or the translator, and has no path
back into the document you were typing in.

What leaves the app is unchanged: one request to YouTube's documented channel
feed and one validated video URL handed to Chrome by `NSWorkspace`. There is **no
scraping, no browser automation, no login, no cookies, no injected script, no
shell and no AppleScript**, and no tab you already had open is read, closed,
reordered or navigated. Autoplay remains Chrome's decision and YouTube's, and
Chrome remains the only application this command opens.

[docs/youtube-latest-video.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/youtube-latest-video.md)
is the whole story, including how to find a channel id.

### This is the build the picker ships in

The picker was written up in the 0.9.1 notes in this repository, but it landed
after the 0.9.1 build was produced and published. **0.9.2 is the first release
that contains it.** If you are on 0.9.1 and the panel never appeared, that is
why.

## A note for anyone building this repository

Pull requests now report a single required **build** check. Continuous
integration ran on every push and on every pull request, which spent two macOS
runners on one branch and still left a window in which a pull request showed no
checks at all - so a review had nothing to wait for. Push builds are now limited
to `master`, and a pull request attaches exactly one build check.

This changes nothing about the application. It is listed here because it is the
other change in this release, and because "the PR has no checks" was a
reproducible way to merge something unbuilt.

## Everything else is unchanged from 0.9.1

- **Every shortcut is where it was.** ⌥` records, ⌥A opens Ask, ⌥S asks about
  the screen, ⌥M switches engine, ⌥Y runs the YouTube command - all rebindable in
  **Settings → Shortcuts**. The optional on-device channel-name matcher is still
  **off by default**, still a chooser rather than a resolver that can only return
  a channel already on your list, still fails closed, still never leaves this
  Mac, and still says so when it is used. It runs before the picker, so a name it
  places still opens without asking you anything.
- **History still says what each entry was** - Dictation, Ask, File
  transcription, YouTube command - and entries from before 0.9.1 are still
  labelled "Older recording" and never relabelled.
  [docs/history-provenance.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/history-provenance.md).
- **Chinese transcripts are still written in one script**, Traditional unless you
  picked Simplified, as an output setting only: it never makes recognition
  Chinese, never moves your dictation language and never touches Japanese or
  Korean.
  [docs/chinese-script.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/chinese-script.md).
- **The cloud path is still opt-in and still off.** Two features can be pointed at
  an OpenAI-compatible provider, speech transcription and the spoken "Translate
  to …" command, and switching either takes an explicit acceptance of a sheet
  naming what is uploaded and where. Style rewriting, the Ask panel (⌥A), screen
  questions (⌥S) and channel-name matching have no cloud path at all, enforced in
  code. A 0.9.2 install you never point at a provider sends nothing, anywhere,
  with the single exception of the YouTube command if you add a channel and use
  it: that request carries a channel id you typed and nothing about you.
  [docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).
  If you need "not present" rather than "not enabled",
  `Scripts/build_release.sh --offline-only` still builds exactly that; it is not
  published as a separate download here.
- **The app is still thin.** It ships no model weights. The model you choose is
  fetched on demand and checksummed, SenseVoiceSmall as a verified model pack and
  every other engine by its own downloader, and lands in Application Support,
  where it survives replacing the app. This build does not change the
  SenseVoiceSmall pack, so an engine you have already downloaded is not fetched
  again.
  [docs/model-packs.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/model-packs.md).
- **Kongweh still never checks for updates on its own.** Checking, downloading
  and installing remain three separate things you press.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try, typically "the app is damaged and
can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

The app in Finder is still `EchoForge.app`; it introduces itself as Kongweh once
it starts.

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording** the
first time you use ⌥S. **This is expected and is not a regression**; it happens
on every unsigned update and will keep happening until these builds are signed
with a Developer ID.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add the
new app back; macOS otherwise keeps showing the old entry as granted while the
new build has nothing. The new entry may appear under either name.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks whether it may
use information stored in your keychain. Choose **Always Allow** and it stops
asking. An install that has never turned the cloud path on never reads the
Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).
