# EchoForge 0.5.1

**You can now ask about what is on your screen.** Press **⌥S**, speak a question,
and the answer arrives on the Ask panel with a thumbnail of exactly what was
captured. Everything else in 0.5.0 - transcription, the engines, the personal
terms dictionary, CJK spacing, style rewriting, spoken commands, voice snippets
and the capsule HUD - is unchanged, and the new shortcut stays out of the way
until you press it.

## Ask about the screen (⌥S)

⌥S takes one picture of the window you are looking at and starts recording a
question about it. Press it again to stop, the same way the recording hotkey
toggles. The answer lands on the same floating Ask panel ⌥A opens, beside the
**Copy**, **Insert into Active App** and **Ask by voice** actions it already had.

Everything happens on this Mac. The screenshot is read with Apple's Vision
framework and answered by the same on-device model style rewriting and the Ask
panel use. Nothing is uploaded, and nothing is written to disk - not the image,
not the text read off it. The screenshot lives in memory for as long as the
conversation on the panel does, and goes when the panel closes.

### What it captures

The window you were actually looking at: EchoForge reads the frontmost
application and starts the capture **before** the panel is drawn, because opening
the panel makes EchoForge frontmost. Within that app it takes the largest
ordinary document window, ignoring inspectors, find bars, the Dock and floating
palettes; with no such window it falls back to the main display.

**EchoForge is never in the picture.** Our own windows are excluded whatever is
asked for, and a display capture excludes the whole application from the filter.

The thumbnail is shown rather than described, because the one real risk of a
screen query is that it captured the wrong window and a picture is the only way
to see at a glance that it did not. It stays with the exchange, so an answer three
questions back still says which screen it was about, and its caption names the
application and window title - and nothing else about them.

### What it is good at, and what it is not

Apple's on-device model takes text prompts only, so the screenshot is read with
OCR and the words are what the model gets. That answers questions about **text on
the screen** well, and questions about colour, layout or an unlabelled image not
at all. Worth knowing before you ask one.

### A screen question is never answered blind

- A capture that fails while you are still speaking **stops** the recording rather
  than carrying on. Answering from your words alone would be a confident reply
  about something nothing ever looked at.
- A question that finishes transcribing before its screenshot arrives **waits** for
  it, with a budget so a wedged capture cannot hang the panel.
- A screenshot is used once, and a capture that lands late - after a cancel, a
  close, or the start of an unrelated follow-up - is dropped rather than attached
  to whatever replaced it.

### Screen Recording permission

Screen Recording is **conditional**, exactly like Input Monitoring: it is read
when you press ⌥S and at no other time, it is not part of the app's polled
permission check, and it never gates the app. An install that never presses ⌥S
never sees a prompt, and dictation is unchanged on a Mac that has refused it.

macOS shows its own dialog once per app and never again, so the first refused ⌥S
leaves that dialog as the thing to act on and the panel simply explains; every
later one points you at System Settings and opens the pane. A grant belongs to
the bundle that asked for it, so a fresh download of EchoForge asks again.

### The screen is data, not instruction

The text read off the screen is fenced and labelled as content, the same way a
transcript is fenced before the rewriting stage sees it - a screen holds text
somebody else wrote, and "ignore your previous instructions" is a sentence anybody
can put on one.

That fence is a mitigation rather than a guarantee, and it does not have to be
more: like the Ask panel, and unlike style rewriting, there is deliberately **no
rewrite guard** here. A guard exists because a rewrite replaces your own words
unread; a screen answer is drawn on a card you read, and reaches another
application only when you press **Insert**.

## Fixed: crash dialogs during release verification

Building a release ran the release-package verifier's own test suite, and three of
its four fixtures proved their point by *starting* a deliberately broken app
bundle. Each such start ends in SIGABRT, and macOS answers that with a crash
report and a "quit unexpectedly" dialog - four of them per run, including every
time the test suite ran.

The defect those fixtures demonstrate is a property of the **signature**, not of
the run: hardened runtime turns library validation on, an ad-hoc signature has no
Team ID to satisfy it, and macOS treats each ad-hoc-signed file as its own
identity. That is now read straight off `codesign`, and the bundles that cannot
start are verified without launching them. A fifth case was added so the
verifier's launch check is still exercised on a failing bundle - one that exits
non-zero without aborting.

Nothing about what the verifier checks changed, and this release was published
only after it passed. This is developer-facing: it does not alter the shipped app.

## Requirements

The Ask panel, screen queries, translation and style rewriting all run on Apple's
on-device model, so they need **macOS 26 or later on a Mac that supports Apple
Intelligence**, with Apple Intelligence switched on in System Settings. On any
other Mac those panes say so plainly and everything else works exactly as before.

## Upgrading

If you are on 0.5.0 this is a straight upgrade: nothing you already use changes
behaviour, and ⌥S does nothing until you press it. If you are still on 0.3.0,
that build could not open on any Mac - install this one instead. See the
[0.5.0 notes](v0.5.0.md) for the Ask panel, spoken commands, voice snippets,
app-aware styles, the Compare view and the capsule HUD.

This build is produced by `Scripts/build_release.sh` and was published only after
`Scripts/verify_release_package.sh` checked every embedded library's signature and
`@rpath` dependency and **started the app**.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try - typically "the app is damaged and
can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**, and
     click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

Replacing an existing install keeps your recordings, personal terms, snippets and
downloaded models. Because these builds are unsigned, macOS treats each one as a
new app for permission purposes, so it will ask for Microphone and Accessibility
again - and if a stale **EchoForge** entry is already listed under **Privacy &
Security → Accessibility**, remove it with the minus button and add the new app
back.

This build ships with SenseVoice-Small on board, so it can dictate as soon as it
is installed.

recording:
