# EchoForge 0.5.0

The biggest release since dictation itself. A dictation no longer has to become
text you typed: it can be a question, a translation, or a macro you stored. The
style it is rewritten into can be chosen by the app you are dictating into. You
can see exactly which words post-processing changed. And the whole thing can be
shown as a pill at the top of the screen instead of a card at the caret.

Everything here is **off by default** except the diff view, which only appears
when you ask for it. Transcription, the engines, the personal terms dictionary
and CJK spacing are unchanged, and none of the new features is a prerequisite
for dictating.

## Compare: see what post-processing changed

Two copies of a paragraph do not answer the question a history row raises -
*which of these words are mine?* So **Compare** now sits beside **Show original**
on every history row, and the Settings Style preview renders its result the same
way: your transcript with everything post-processing dropped or replaced still in
place, struck through and muted.

- It covers **all** post-processing, not just style rewriting - the personal terms
  dictionary and CJK spacing show up too.
- The final text is reproduced character for character. A comparison that quietly
  reworded the result would be worse than none.
- Case and whitespace alone are never marked up. A style that capitalises a
  sentence has not changed a word, and saying it did would bury the changes that
  are real.
- Chinese is compared per character rather than per phrase, so a CJK comparison is
  something you can read instead of one enormous replacement.

## The floating capsule HUD

An alternative to the caret-anchored indicator card: one pill at the top of the
screen that says what the app is doing with your voice. Turn it on in
**Settings → Shortcuts → Recording Behavior → Floating capsule HUD**.

It shows a live input level meter, how long you have been talking, and a chip
naming what is about to happen to the words (`Dictate`, `Polish`, `Formal`,
`Bullets`, …). Once the audio stops it shows `Transcribing…`, then `Polishing…`
if a rewrite is running, and it ends on a checkmark - or an orange badge with one
sentence saying what went wrong.

- It **replaces** the card rather than joining it. They are two presentations of
  the same dictation, so the app picks one when the session starts.
- The level meter is scaled in decibels, not amplitude, so normal speech fills
  about 60 % of the bar instead of barely moving it.
- The capsule never takes keyboard focus. Dictation ends by pasting into whatever
  app you were typing in, and a HUD that stole focus would change where the text
  lands.
- A cancelled or failed dictation can no longer end on a checkmark, and when a
  promised rewrite kept your original the badge tells you why instead of a
  checkmark papering over it.

With the HUD switched off, the level metering is not running and costs nothing.

## Match the style to the app you dictate into

Dictating into Slack and dictating into a mail composer are not the same piece of
writing. Turn on **Match the style to the app I dictate into** (Settings → Style,
under the style list) and the style is resolved from the app the words are going
into:

| Category | Style |
| --- | --- |
| Chat | Casual Chat |
| Mail | Formal Business |
| Code and terminals | Grammar & Polishing |
| Documents and notes | Grammar & Polishing |
| Browsers | the style you chose |
| Anything unrecognised | the style you chose |

You can override any category, and set a rule for one specific app that beats its
category.

### What it is allowed to know

**The frontmost application's bundle identifier. Nothing else.** No window title,
no document name, no web address, no page content. Nothing is sent anywhere - the
whole resolution is a dictionary lookup on your Mac - and nothing is logged,
including the identifier itself. That is the shape of the code rather than a
promise on top of it, and the tests fail if a window-title, address, network or
logging call is added to either source file.

Browsers deliberately get no default for the same reason: a browser window is a
mail client, a chat client and a code review on three tabs, and only the page's
address would tell them apart. Set a rule for your browser by hand if you live in
one web app.

Two rules carry it. A mapping chooses **which** style runs, never **whether** one
runs, so no app can switch the model on for words you did not agree to send it.
And a week of dictating into Slack never ends with "Casual Chat" selected in
Settings - the style you chose and the style a dictation used stay two different
values.

## Spoken commands, and the Ask panel

With **Spoken commands** on (Settings → Shortcuts → Ask & Spoken Commands, off by
default), three things you can say instead of dictating:

| Said | What happens |
| --- | --- |
| `Ask: what is a good subject line for this?` / `請問…` | the question goes to the Ask panel |
| `Translate to Spanish: the meeting starts at three` / `翻譯成西班牙文：…` | the translation is pasted instead of the words |
| `insert email signoff` / `插入會議記錄` | your stored template is pasted (see below) |
| anything else | dictation, byte for byte |

**Everything unrecognised is dictation.** No model classifies what you said -
that would put a model in front of every dictation and cost a second of latency
on the plain path that is almost all of the traffic. The router is pure grammar,
and a marker that is also an ordinary word ("ask", "問") is only promoted when the
transcript shows the pause a real command has, so "Ask him to call me back" stays
a sentence you dictated.

Routing only runs for live dictation. A dropped file, a queued recording, a
regenerate from history and the Ask panel's own voice follow-up all take the plain
path.

### The Ask panel

**⌥A**, or a spoken question, opens a floating card that answers on this Mac,
using the same Apple on-device model style rewriting uses. Four actions: **Copy**,
**Insert into Active App**, **Ask by voice**, and **Close** (also Esc). You can
keep asking - the conversation is held while the panel is open and is written
nowhere.

This is the one overlay in the app that takes keyboard focus, because a question
box has to. So the app to paste into is captured **before** the panel opens and
brought back for the Insert, rather than read at insertion time - and if there is
no target, the answer goes to the clipboard rather than into whatever happens to
be frontmost. Closing the panel hands your keystrokes back to where they came
from.

There is deliberately **no rewrite guard** on an answer. That guard exists because
a rewrite replaces your own words unread; an answer is on a card you are looking
at and reaches another app only when you press Insert.

### Translation

Translation is its own stage rather than a style, because every rule the rewriting
stage sends says *stay in this language and never translate* - and translation is
the one request where all of that is backwards. The instruction is written in the
target language, which is what makes the answer come out in it.

The safety checks still apply: numbers, currency and percent symbols, your
personal terms, and the model answering you instead of translating. Only the
script check is relaxed, and only for a translation. If the model is unavailable,
slow or its answer is refused, you get the body of what you said with the spoken
command stripped - pasting "Translate to Spanish: hello" into your document would
be worse.

Named Chinese variants are respected: `翻譯成繁體中文` and `translate to simplified
chinese` are different requests.

## Voice snippets

A macro, not a rewrite. Store a trigger and a template in **Settings → Dictionary
& Snippets**, then say **"insert email signoff"** - or just **"email signoff"** on
its own - and the template goes in instead of the words.

- **The template is inserted byte for byte.** The rewriting stage is never
  consulted: blank lines, indentation and a deliberate missing full stop are your
  formatting, and a model asked to polish a form returns prose about a meeting.
- **Nothing partial ever fires.** A trigger has to match in full, and the bare
  form only when the trigger is the entire dictation. "Insert a row above this
  one" and "the email signoff was wrong" both stay dictation.
- Case, surrounding punctuation, run-together spacing and Traditional against
  Simplified are all folded away, because each of those is the speech engine's
  choice rather than yours.
- The built-in commands are matched first, so a trigger can never take `Ask:` or
  `Translate to …` away from them.
- Two samples are seeded once on a fresh install. Deleting them sticks.

Snippets can be switched off on their own (`Voice snippets`, on by default)
without also switching off Ask and Translate. History keeps what you said -
"insert email signoff" - alongside the text that was inserted.

## Requirements

The Ask panel, translation and style rewriting all run on Apple's on-device model,
so they need **macOS 26 or later on a Mac that supports Apple Intelligence**, with
Apple Intelligence switched on in System Settings. On any other Mac those panes
say so plainly and everything else works exactly as before.

The capsule HUD, app-aware style mapping, voice snippets and the Compare view have
no such requirement - though a style mapping obviously only does something while
rewriting is on.

## Upgrading

If you are on 0.4.1 this is a straight upgrade; nothing you already use changes
behaviour, and every new feature stays off until you turn it on. If you are still
on 0.3.0, that build could not open on any Mac - install this one instead.

This build is produced by `Scripts/build_release.sh` and was published only after
`Scripts/verify_release_package.sh` checked every embedded library's signature and
`@rpath` dependency and **started the app**.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try - typically "the app is damaged and
can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**, and
     click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

Replacing an existing install keeps your recordings, personal terms, snippets and
downloaded models. Because these builds are unsigned, macOS treats each one as a
new app for permission purposes, so it will ask for Microphone and Accessibility
again - and if a stale **EchoForge** entry is already listed under **Privacy &
Security → Accessibility**, remove it with the minus button and add the new app
back.

This build ships with SenseVoice-Small on board, so it can dictate as soon as it
is installed.

recording:
