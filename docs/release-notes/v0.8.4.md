# EchoForge 0.8.4

**The YouTube command has a key of its own, and dictation went back to being
text and only text.** In 0.8.3 that command rode on the dictation shortcut as a
spoken marker, which meant every dictation had to be read for it first and a
mis-read one could open a browser instead of typing what was said. It is now
**⌥Y**, a separate key that records a command and nothing else. Nothing else
about recognition, transcripts, styles or storage changes in this build, and
recordings, personal terms, snippets, styles, shortcuts and downloaded models
are untouched by this update.

## ⌥Y opens a listed channel's newest video, and only that

Hold **⌥Y**, say **"Veritasium"**, let go, and that channel's newest video opens
in a new Chrome tab. Because the key already says what the utterance is for, the
marker phrase is now **optional**: the channel name on its own is the whole
command. The old sentences still work, in English and Chinese ("open the latest
YouTube video from …", "打開YouTube最新影片…", "播放…", with or without spaces).

The key is bound in **Settings → Shortcuts → YouTube Command**; ⌥Y is only the
default, alongside ⌥` (record), ⌥A (Ask), ⌥S (ask about the screen) and ⌥M
(switch engine). The channel list and the feature's own switch are in
**Settings → Dictionary & Snippets → YouTube Channels**.

### Two keys, and that is the safety story

- **Your dictation shortcut produces text and only text.** The router that reads
  dictations no longer has a case that opens anything, so no transcript that key
  captured can reach a browser however it is worded. Saying "open the latest
  YouTube video from Veritasium" into your dictation key **types those words**,
  the way it did before this feature existed.
- **The command key produces no text at all.** What ⌥Y captured is read only as
  a channel name. It never reaches style rewriting, the Ask panel, the snippet
  expander or the translator, and there is no path from it back into the
  document you were typing in.

Which of the two a recording is belongs to the press that captured it, not to a
setting, and everything else in the app (a dropped file, a queued recording, a
regenerate from History, the Ask panel's own follow-up) is a dictation and
cannot become anything else. The recording is kept in History either way.

The feature switch is **on by default** now and is independent of spoken
commands, which stay off. That is not a change to anyone's dictation: on a fresh
install it governs a key nobody has pressed against an **empty** channel list,
so nothing can be opened until you add a channel yourself. With the switch off
the key stays bound and a press says the feature is off, rather than reading as
a dead key.

### Only the channels you configured can ever open

**The allowlist is the security model, and it is the whole of it.** A channel is
named by the canonical `UC…` id you paste into Settings yourself. Nothing
resolves a `@handle`, nothing searches YouTube, and nothing turns spoken words
into an address, so **no spoken name can reach a channel that is not on your
list**. A name that is not there, or one that two of your rows answer to, opens
nothing and says why.

What leaves the app is unchanged from 0.8.3: one request to YouTube's documented
channel feed and one validated video URL handed to Chrome by `NSWorkspace`,
which is the same thing clicking a link does. There is **no scraping, no browser
automation, no login, no cookies, no injected script, no shell and no
AppleScript**, and no tab you already had open is read, closed, reordered or
navigated. The feed parser still refuses a document that declares XML entities
outright, is bounded in size and entry count, and repairs nothing.

**Autoplay is Chrome's decision, not this app's.** Whether the video starts on
its own, and whether it starts muted, is Chrome's autoplay policy and YouTube's.
Nothing here tries to influence either, and the Settings pane says so. Chrome is
also the only application this command opens; if Chrome is not installed the
command says so and opens nothing.

## Spacing no longer has to match

Matching a spoken name is now two deterministic tiers instead of one. The first
is the stored spelling as before, with case, edge punctuation, doubled-up
whitespace and Traditional against Simplified script folded away. The second is
that same comparison **with internal spaces folded away too**, so a channel
stored as `valley101` answers to "valley 101" and one stored as `小Lin說`
answers to "小 Lin 說".

Where a space falls inside a name is the one variation a speaker cannot control:
you say "valley one oh one" and the engine writes it one way today and the other
tomorrow. Nothing is stemmed, truncated or partially matched, so `valley`,
`valley 10` and `valley 1012` still reach nothing.

**Ambiguity is detected in each tier separately and separately refused**, so
widening the comparison can never quietly pick a winner. Two rows that differ
only in spacing each stay reachable by their own exact spelling.

## An optional on-device fallback, off by default

When what you said matches no channel, or matches two, EchoForge can ask Apple's
on-device model which of **your** channels you meant. It is **off by default**
(Settings → Dictionary & Snippets → YouTube Channels, "Let the on-device model
match a name I said"), and the pane says what it does before you switch it on.

- **It is a chooser, never a resolver.** It is given the words you said and a
  numbered list of the display names and aliases already on your list, and
  **no channel ids, no URLs and no hosts**. Its answer is looked up in that same
  list, so **it cannot select a channel you did not configure and cannot produce
  an address at all**: an invented name, a `UC…` id, a URL or an instruction
  matches nothing.
- **It runs last and only on a failure.** A name your own spellings already
  matched is never re-asked, so nothing about it is on the path for most people.
- **It fails closed.** No model on this Mac, Apple Intelligence off, a model
  still downloading, a timeout, an error, an answer that is not one of your
  rows, an answer two of your rows answer to, a list or an utterance past its
  caps: every one of those leaves the original refusal exactly as it was, and
  nothing is opened.
- **It never leaves this Mac.** There is no cloud path for it, enforced in code
  the same way style rewriting, the Ask panel and screen questions are. Your
  dictation never reaches it either way; only what you say into ⌥Y does.
- **It is disclosed when it is used.** A match the model made says so, in the
  log and in the VoiceOver announcement.

[docs/youtube-latest-video.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/youtube-latest-video.md)
is the whole story, including how to find a channel id.

## Everything else is unchanged from 0.8.3

- **Chinese transcripts are still written in one script**, Traditional unless
  you picked Simplified, as an output setting only: it never makes recognition
  Chinese, never moves your dictation language and never touches Japanese or
  Korean.
  [docs/chinese-script.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/chinese-script.md).
- **The cloud path is still opt-in and still off.** Two features can be pointed
  at an OpenAI-compatible provider, speech transcription and the spoken
  "Translate to …" command, and switching either takes an explicit acceptance of
  a sheet naming what is uploaded and where. Style rewriting, the Ask panel
  (⌥A), screen questions (⌥S) and the channel matching above have no cloud path
  at all, enforced in code. A 0.8.4 install you never point at a provider sends
  nothing, anywhere, with the single exception of the YouTube command if you add
  a channel and use it: that request carries a channel id you typed and nothing
  about you.
  [docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).
  If you need "not present" rather than "not enabled",
  `Scripts/build_release.sh --offline-only` still builds exactly that; it is not
  published as a separate download here.
- **The app is still thin.** It ships no model weights. The model you choose is
  fetched on demand and checksummed, SenseVoiceSmall as a verified model pack
  and every other engine by its own downloader, and lands in Application
  Support, where it survives replacing the app. This build does not change the
  SenseVoiceSmall pack, so an engine you have already downloaded is not fetched
  again.
  [docs/model-packs.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/model-packs.md).
- **The ⌥M engine shortcut and the Settings tab bar are as they were** in 0.8.3.
- **EchoForge still never checks for updates on its own.** Checking,
  downloading and installing remain three separate things you press.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try, typically "the app is damaged and
can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording** the
first time you use ⌥S. **This is expected and is not a regression**; it happens
on every unsigned update and will keep happening until these builds are signed
with a Developer ID.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add
the new app back; macOS otherwise keeps showing the old entry as granted while
the new build has nothing.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks "EchoForge
wants to use information stored in your keychain". Choose **Always Allow** and
it stops asking. An install that has never turned the cloud path on never reads
the Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).
