# EchoForge 0.9.5

**History stops being a list you can only scroll, and the dictation path stops
doing work nobody asked for.** You can now search every entry you ever recorded
and save one out as a Markdown or plain-text file - both entirely on your Mac,
with nothing sent anywhere. Cancelling a queued transcription now actually
cancels it instead of quietly running it again a moment later, and a microphone
that fails to open says so rather than showing you a card that records nothing.
Nothing about recognition, storage or the security model changes in this build,
and your recordings, personal terms, snippets, styles, shortcuts and downloaded
models are untouched by this update.

> The download is still `EchoForge.dmg` and it still installs `EchoForge.app`.
> The app introduces itself as Kongweh once it starts. That split is deliberate -
> see "One app, two names" in the 0.9.1 notes.

## Search your whole history, not just what is on screen

There is a search box at the top of the window, and **⌘F** puts the caret in it.
It is always there rather than sliding into view, so the key moves focus rather
than revealing anything.

**It searches your whole history, not the page in front of you.** History is
loaded a hundred rows at a time, so a search that only looked at what had already
been loaded would silently hide the older entry you are actually hunting for. The
match runs in the database instead, which means a phrase from last month finds
last month's dictation. Typing is smoothed out by a fifth of a second so a long
history never stalls the keystroke that produced it.

A phrase is matched, case-insensitively, against five things at once:

- **the words in the transcript**, and **what the engine heard** before
  post-processing - the text behind "Show original";
- **the label on the entry**, so typing `voice edit` finds your voice edits and
  `youtube` finds both YouTube outcomes;
- **the sentence under the label**, including the reason a command that opened
  nothing gives;
- **a date**, written `2026-09-05` for a day, `2026-09` for a month, `2026` for a
  year, or the way the entry itself prints it (`Sep 5, 2026`).

Only those date spellings are read as dates. Nothing here guesses: "yesterday"
depends on the reader's locale as much as on the clock, and a wrong guess would
move your search a day without telling you - so any phrase that is not one of
those spellings is left to the text match, where it can only find rows rather
than hide them.

**The kind filter beside the box narrows a search rather than replacing it.**
Typing a word and then choosing "Voice edit" gives you the voice edits carrying
that word. When nothing matches, the panel says what was searched for and offers
**Clear search**, which is the one way back to everything and is the same action
as the field's own ⓧ.

### Two things it deliberately never searches

**The internal audio file name and the path a dropped file came from.** One is a
`UUID.wav` you have never seen; the other is an absolute path on your disk whose
folder names have never appeared on a card. A match on either would be an
accident of where you keep your files, and one more way for a folder name to end
up on screen in front of somebody.

And a search field is not a pattern language: typing `100%` searches for `100%`,
not for every entry beginning `100`.

## Save a transcript out as a file

Hover a finished entry that has words - or right-click it - and choose **Export
transcript**. A normal save panel asks where it goes, and a **Format** menu at
the bottom of it asks what to write:

- **Markdown (.md)**, the default. The details are a short list and the words sit
  in a fenced block, so a dictation containing a `#`, a `*`, a `|` or a line of
  dashes reads back as **what you said** rather than as somebody else's headings,
  emphasis and tables. A dictation *about* code cannot close the fence early
  either.
- **Plain Text (.txt)** - the same details and the same words with no markup, for
  anything that has no Markdown reader.

The extension and the contents can never disagree: if you pick Markdown and then
type `notes.txt`, you get plain text, because the name is what you are left
holding. A bare `notes` takes the format the menu is showing.

Three things about it are worth knowing:

- **The only file written is the one you pointed at.** Nothing is written beside
  the recording, into Application Support, or anywhere you did not choose, and
  the panel's own overwrite confirmation is the only overwrite there is.
- **Nothing leaves the device.** There is no share sheet, no upload and no
  network call anywhere in this path.
- **The document says only what the card says** - the transcript, the original
  behind "Show original", the timestamp, the label and its sentence, the duration
  and the "AI Polished" chip. It never carries the entry's internal id, the audio
  file name or the absolute path a dropped file came from, because a file you are
  about to mail to somebody must not carry the layout of your disk. The suggested
  file name is the date and the kind, and nothing from the transcript: the first
  words of a dictation are exactly what you would not want showing in a Finder
  window behind you.

Cancelling says nothing - you know what you just did. A refused write shows the
system's own reason on the card, inline and dismissible, never as an alert. An
entry still running, a failed one, or a finished one with no words is not offered
the button at all.

[docs/history-search-export.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/history-search-export.md)
is the whole story.

## A cancelled transcription is now actually cancelled

Two bugs sat behind that sentence, and both could put words on your screen that
you had told the app to drop.

**A cancelled queue item was transcribed again.** Cancelling only noted the id;
the entry itself was left in a state the queue reads as still-to-do, so the loop
was handed the same recording back on its next turn and ran it through the engine
a second time. That was a whole duplicate decode, in front of every dictation
queued behind it, with live dictation refused for the duration - and on the cloud
engine, a second paid request nobody asked for. Every path out of a pass now
settles the entry, and the rule turns on whether the last pass actually made
progress rather than on which row it was, so **regenerating a recording that just
finished is still new work** rather than being mistaken for a repeat.

**Cancelling a live dictation could still paste its transcript.** The cancel flag
was raised and dropped again within one call, so every check of it inside the
running transcription read "not cancelled" and an engine that answered a moment
too late had its text pasted anyway. Worse, cancelling cleared the app's own
answer to "is the engine busy", so a press immediately afterwards could start a
second transcription on an engine still working on the first. Both are now scoped
to the dictation that owns them: **one dictation's cancellation cannot reach the
next**, and a press right after a cancel waits for the engine rather than racing
it.

**And the queue always stops being busy.** While it believes it is working, it
refuses to start a dictation at all - so a loop that failed to return was not a
stuck entry, it was an app that no longer dictates. It now always releases, and
gives up on an entry it cannot settle instead of spinning on it.

Nothing here retries anything: a cancelled item is written down as cancelled and
a failed one as failed, and neither runs again unless you press regenerate.

## A microphone that never opens now says so

Pressing a key claims the microphone straight away, but the audio hardware is
opened a few tens of milliseconds later - so **a start can fail after the card is
already up**. When it did, nothing said so: the dictation card blinked
**Recording...** over a microphone that had never started and then vanished
without a word, and the Ask panel reported the same failure as "No speech
detected", which sent people looking for a problem with their voice.

A start that fails is now reported as a failure, by name, to whichever press
made it - and every surface that takes the microphone listens for it: the
dictation card, the Ask panel, and the main window's record button, which
previously had nothing at all to go on.

## What a dictation actually costs, and what was left alone

This release also came out of measuring the dictation path end to end, and the
useful result is mostly **negative**: three plausible "the app is doing too much
work per dictation" hypotheses were tested and all three were rejected rather
than acted on. Re-checking the model cache at the head of each transcription
costs 0.10 ms; building the settings for a dictation, including reading your
personal terms, costs 0.006 ms; a whole recording's hundred progress updates cost
3.3 ms between them and touch the database not at all.

Each of those "optimisations" would have traded a real guarantee - such as
noticing that a model was deleted while the app was running - for a fraction of a
millisecond, so none was made. What actually dominates a dictation is the engine
decode and, when it is on, the rewriting stage; both are the product's chosen
quality rather than overhead. The one genuinely large avoidable cost was the
queue re-running cancelled work, which is fixed above. One small change was worth
making: the recording's duration is now read while the engine works instead of
before it starts, since its answer is not needed until the entry is written.

The numbers and the rejected hypotheses are written down in
[docs/dictation-latency.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/dictation-latency.md)
so nobody has to re-measure them.

## Everything unchanged from 0.9.4

- **Search and export are local, and add nothing to what leaves your Mac.**
  Neither asks a model anything and neither touches the network.
- **Every shortcut is where it was.** ⌥` records, ⌥A opens Ask *and listens*, ⌥S
  asks about the screen, ⌥E edits highlighted text, ⌥M switches engine, ⌥Y runs
  the YouTube command - all rebindable in **Settings → Shortcuts**. ⌘F is a
  focus key inside the main window and takes nothing from them.
- **The microphone is still owned by whichever press took it**, so a dictation,
  an Ask, a screen question and a voice edit cannot end one another's recording;
  a press arriving while something else is listening is refused rather than
  interrupting it. What is new is only that a refusal caused by hardware that
  never opened is now reported instead of being silent.
- **History still says what each entry was** - Dictation, Ask, Voice edit, File
  transcription, YouTube command - and entries from before 0.9.1 are still
  labelled "Older recording" and never relabelled. The sentence under a label
  holds no channel ID, feed address, video URL or anything from your Keychain,
  and neither does an exported file.
  [docs/history-provenance.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/history-provenance.md).
- **✨ Fix with AI and ⌥E voice edit are unchanged**, on-device only and with no
  cloud path, as they were in 0.9.4.
- **Chinese transcripts are still written in one script**, Traditional unless you
  picked Simplified, as an output setting only: it never makes recognition
  Chinese, never moves your dictation language and never touches Japanese or
  Korean.
  [docs/chinese-script.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/chinese-script.md).
- **The cloud path is still opt-in and still off.** Two features can be pointed
  at an OpenAI-compatible provider, speech transcription and the spoken
  "Translate to …" command, and switching either takes an explicit acceptance of
  a sheet naming what is uploaded and where. Style rewriting, Fix with AI, voice
  edit (⌥E), the Ask panel (⌥A), screen questions (⌥S) and channel-name matching
  have no cloud path at all, enforced in code. A 0.9.5 install you never point at
  a provider sends nothing, anywhere, with the single exception of the YouTube
  command if you add a channel and use it: that request carries a channel id you
  typed and nothing about you.
  [docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).
  If you need "not present" rather than "not enabled",
  `Scripts/build_release.sh --offline-only` still builds exactly that; it is not
  published as a separate download here.
- **Kongweh still never checks for updates on its own.** Checking, downloading
  and installing are three separate things you press, and an update is only ever
  downloaded from this repository's own GitHub releases.
- **The app is still thin.** It ships no model weights. The model you choose is
  fetched on demand and checksummed, SenseVoiceSmall as a verified model pack and
  every other engine by its own downloader, and lands in Application Support,
  where it survives replacing the app. This build does not change the
  SenseVoiceSmall pack, so an engine you have already downloaded is not fetched
  again.
  [docs/model-packs.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/model-packs.md).

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try, typically "the app is damaged and
can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

The app in Finder is still `EchoForge.app`; it introduces itself as Kongweh once
it starts.

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording** the
first time you use ⌥S. **This is expected and is not a regression**; it happens
on every unsigned update and will keep happening until these builds are signed
with a Developer ID.

Searching and exporting history need no permission at all - both read a database
that is already yours, and the save panel is what grants access to the folder you
choose.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add
the new app back; macOS otherwise keeps showing the old entry as granted while
the new build has nothing. The new entry may appear under either name.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks whether it
may use information stored in your keychain. Choose **Always Allow** and it
stops asking. An install that has never turned the cloud path on never reads the
Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).

Produced by `Scripts/build_release.sh` and published only after
