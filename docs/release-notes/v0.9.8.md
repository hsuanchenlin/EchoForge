# EchoForge 0.9.8

**History cards can be edited by hand, and a dictation that never comes back
no longer holds the app.** The live preview writes Chinese in the script you
chose once an explicit Chinese dictation language is chosen, or once Whisper
pins Chinese, so those words on the capsule match the paste. The engine is
reserved before it loads, a hung decode times out instead of waiting forever,
and several files dropped in the same second each keep their own recording.
Your recordings, personal terms, snippets, styles, shortcuts and downloaded
models are untouched by this update.

> The download is still `EchoForge.dmg` and it still installs `EchoForge.app`.
> The app introduces itself as Kongweh once it starts. That split is deliberate -
> see "One app, two names" in the 0.9.1 notes.

## Edit a transcript on the card

A finished history row that has words now offers **Edit transcript** - the
pencil on the hover bar, the right-click menu, and VoiceOver - beside play,
copy, export, Fix with AI, regenerate and delete.

A press replaces the static transcript with an inline editor, **Save** and
**Cancel**. ⌘↩ saves, Escape cancels. Save is disabled while the draft is
empty, so a recording cannot be blanked into "No speech detected". A failed
write leaves the editor open with the draft still there; a write that lands,
or a regeneration that superseded it, closes the editor.

The original words are kept. If the row had no original yet, the text the
card showed before the edit is stored as that original, so **Show original**
and **Compare** still have something to disclose. A row that already stores
an original - post-processing, Fix with AI, or a previous edit - leaves that
copy alone. The "AI Polished" mark is cleared, because the words on the card
are now yours.
[docs/history-card.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/history-card.md)
is the whole story.

## The live preview writes Chinese in your script once the language is Chinese

**Settings → Transcription → Chinese Output Script** already decided the
paste: Traditional by default, Simplified if you pick it. The capsule's
growing line used to show whatever the engine returned, so a Traditional
writer watched Simplified on screen and then received Traditional in the
document.

The preview now converts the copy made for the screen, and nothing else,
when an explicit Chinese dictation language is chosen, or when Whisper pins
Chinese. The engine's own words are what `finish` still hands to the paste,
and the transcript stage still converts those. SenseVoice, Paraformer and
Parakeet never pin a language, so a live dictation left on Automatic keeps
the engine's own script on the capsule for the whole recording; the paste
still converts. A session pinned to Japanese shows kanji as the engine
returned them. The line only ever grows: each utterance is converted once
as it commits, so a detection that lands mid-session decides the script of
the words after it and never rewrites what you already read.
[docs/live-dictation.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/live-dictation.md),
[docs/chinese-script.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/chinese-script.md).

## A dictation that never comes back now times out

A load or a decode that hangs used to hold the engine for the life of the
process. The waits are now bounded:

- A load has 900 seconds - above the observed cold Neural Engine compile
  under pressure, and finite when model loading is deadlocked.
- A decode has `max(120 s, 10 × audio duration)`, so a short dictation has
  room for a loaded machine and a long file stays proportional to the work.

When the deadline is missed the engine instance is discarded, the recording
is kept, and History can regenerate it. There is no automatic engine
fallback, because changing engines can change language support without you
choosing that tradeoff.
[docs/dictation-latency.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/dictation-latency.md).

## Two transcriptions can no longer share the engine

Every transcription - a dictation, a live utterance, a queued file, a
post-processing pass alone - now reserves the engine *before* the model
loads. A second caller arriving while the first is still preparing used to
find no task and run beside it on the same engine. That overlap is gone: the
second waits, a cancel during the load stops that frame, and a failed load
gives the engine back rather than holding every later transcription for the
life of the process.

The microphone, the "Polishing…" line and the spoken-command chip stay with
the session that asked. A History Fix with AI no longer paints the capsule
of a dictation that has already finished.

Dropped files each keep their own audio. Several files arriving in the same
second used to become distinct history rows pointing at one `.wav`; deleting
any of them removed the audio of all of them. New rows are named by the
row's own id. Rows written before this keep their old names and are never
renamed.
[docs/history-storage.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/history-storage.md).

## Everything unchanged from 0.9.7

- **Live transcription is still on by default.** Turning it off restores the
  whole-file decode exactly, and once off it stays off through later
  updates: the default only fills in for a switch nobody has touched.
  [docs/live-dictation.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/live-dictation.md).
- **The cloud path is still opt-in and still off**, and live transcription
  does not weaken it: the cloud engine is never given a live session, so a
  dictation to your own provider is still exactly one request. Two features
  can be pointed at an OpenAI-compatible provider, speech transcription and
  the spoken "Translate to …" command, and switching either takes an
  explicit acceptance of a sheet naming what is uploaded and where. Style
  rewriting, Fix with AI, voice edit (⌥E), the Ask panel (⌥A), screen
  questions (⌥S), channel-name matching and app vocabulary have no cloud
  path at all, enforced in code. A 0.9.8 install you never point at a
  provider sends nothing, anywhere, with the single exception of the
  YouTube command if you add a channel and use it: that request carries a
  channel id you typed and nothing about you.
  [docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).
  If you need "not present" rather than "not enabled",
  `Scripts/build_release.sh --offline-only` still builds exactly that; it is
  not published as a separate download here.
- **Every shortcut is where it was.** ⌥` records, ⌥A opens Ask *and
  listens*, ⌥S asks about the screen, ⌥E edits highlighted text, ⌘F focuses
  history search, ⌥M switches engine, ⌥Y runs the YouTube command - all
  rebindable in **Settings → Shortcuts**. Pausing from the menu bar stands
  them all down at once and is forgotten when you quit.
- **History still says what each entry was** - Dictation, Ask, Voice edit,
  File transcription, YouTube command - and entries from before 0.9.1 are
  still labelled "Older recording" and never relabelled. Search (⌘F) and
  **Export transcript** are unchanged, still entirely local, and an
  exported file still carries no row id, audio file name or source path.
- **The app is still thin.** It ships no model weights. The model you
  choose is fetched on demand and checksummed, SenseVoiceSmall as a
  verified model pack and every other engine by its own downloader, and
  lands in Application Support, where it survives replacing the app. This
  build does not change the SenseVoiceSmall pack, so an engine you have
  already downloaded is not fetched again.
  [docs/model-packs.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/model-packs.md).
- **Kongweh still never checks for updates on its own.** Checking,
  downloading and installing are three separate things you press, and an
  update is only ever downloaded from this repository's own GitHub
  releases.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try, typically "the app is damaged
and can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Download `EchoForge.dmg`. Its SHA-256 is published beside it as
   `EchoForge.dmg.sha256`, and `shasum -a 256 EchoForge.dmg` is how you check
   it.
2. Open the disk image and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
3. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in
     Terminal (adjust the path if you installed it elsewhere).

The app in Finder is still `EchoForge.app`; it introduces itself as Kongweh
once it starts.

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording**
the first time you use ⌥S. **This is expected and is not a regression**; it
happens on every unsigned update and will keep happening until these builds are
signed with a Developer ID.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add
the new app back; macOS otherwise keeps showing the old entry as granted while
the new build has nothing. The new entry may appear under either name.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks whether it
may use information stored in your keychain. Choose **Always Allow** and it
stops asking. An install that has never turned the cloud path on never reads
the Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).
