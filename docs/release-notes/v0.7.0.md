# EchoForge 0.7.0

**EchoForge can now send speech to a provider you choose, with an API key you
own - and it does not, until you say so.** This release adds one optional path
off this Mac and nothing else. Every previous release ran entirely on your
machine; a 0.7.0 install that you never touch does too, byte for byte.

Two features can be pointed at a provider: **speech transcription** and the
spoken **"Translate to …"** command. Both start on **On my Mac**, and switching
either one takes an explicit acceptance of a sheet that names what will be
uploaded and where.

## Settings → Cloud

One new pane, because a person deciding whether their dictation leaves their Mac
should see every part of that decision at once rather than meeting it twice as
an unremarkable toggle inside some other tab.

| | |
| --- | --- |
| **Speech transcription** | *On my Mac* / *Cloud*. Default: On my Mac. |
| **Translation** (the spoken "Translate to Spanish" command) | *On my Mac* / *Cloud*. Default: On my Mac. |
| **Base URL** | `https://api.openai.com` by default. Any OpenAI-compatible provider works - paste the base URL from their documentation, with or without the trailing `/v1`. |
| **API key** | Yours. Press Save and it goes into your Mac's **Keychain**. |
| **Speech model** | Free text, `whisper-1` by default. |
| **Text model** | Free text, `gpt-4o-mini` by default. |

The two model fields are free text because every provider names its models
differently. On OpenAI, **`gpt-4o-transcribe` is the more accurate speech
model** and costs more per minute than `whisper-1`; type it into **Speech
model** if you want it. Neither field is a menu of blessed choices, so a local
Ollama or LM Studio server naming its models its own way works the same way.

**The consent sheet is the decision, not the toggle.** The first time you switch
a feature to Cloud, a sheet says what will be uploaded, which host it goes to,
that what the provider does with it is their decision and not EchoForge's, that
your key lives in the Keychain, and that you can switch back at any time. The
feature does not change until you accept. Consent is recorded per feature and
survives turning that feature off and on again, because asking twice would just
train people to click through it.

**Forget key and turn everything back to on-device** at the bottom of the pane
deletes the Keychain item, forgets both consents, and puts both features back on
your Mac.

## What leaves your Mac, and what never does

| Feature | Default | What is uploaded when you turn it on |
| --- | --- | --- |
| Speech transcription | **On your Mac** | The audio of each dictation, its language code, and your "initial prompt" setting |
| Translation | **On your Mac** | The text of the dictation you asked to have translated |
| Style rewriting | On your Mac | Never offered a cloud option |
| Ask panel (⌥A) | On your Mac | Never offered a cloud option |
| Screen questions (⌥S) | On your Mac | Never offered a cloud option |
| Personal terms, CJK spacing, voice snippets | On your Mac | No model is involved at all |

Nothing else is sent: no window titles, no bundle identifiers, no history, no
telemetry, no usage counts. EchoForge has no server of its own and proxies
nothing - requests go from your Mac straight to the address in the base-URL
field, and your key is sent to that address and nowhere else. That style
rewriting, Ask and screen questions have no cloud path is enforced in the code
rather than left to convention, and pinned by a test.

The full table, the rules the code keeps, and how to point this at a provider
running on your own machine:
[docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).

## When a cloud dictation fails

No network, a refused key, a rate limit, a provider outage: all of them end the
same way. **Your recording is kept**, carrying the reason, and the regenerate
button transcribes it once the reason is dealt with or once you switch back to a
local engine.

A failed cloud transcription is never quietly retried on a local model. A
fallback would mean you could not tell which engine produced any given
transcript, so EchoForge says what happened instead. Recordings over 25 MB -
about thirteen minutes - are refused before the upload starts rather than after.

## A build with no cloud path at all

If "not enabled" is not good enough and you need "not present",
`Scripts/build_release.sh --offline-only` produces exactly that build: no Cloud
pane, no reachable provider, and a preferences file copied from an ordinary
build cannot switch anything on. Everything else about the app is identical.
That variant is not published as a separate download here; build it from source
if you need it.

## Nothing else has changed

The app is still **thin** - it ships no model weights, and the model you choose
is fetched on demand and checksummed, exactly as in 0.6.0. **EchoForge still
never checks for updates on its own**: checking, downloading and installing
remain three separate things you press. Recordings, personal terms, snippets,
styles and settings are untouched by this update.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try - typically "the app is damaged
and can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording** the
first time you use ⌥S. **This is expected and is not a regression** - it happens
on every unsigned update and will keep happening until these builds are signed
with a Developer ID.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add
the new app back; macOS otherwise keeps showing the old entry as granted while
the new build has nothing.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks "EchoForge
wants to use information stored in your keychain". Choose **Always Allow** and
it stops asking. An install that has never turned the cloud path on never reads
the Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).
