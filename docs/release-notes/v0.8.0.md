# EchoForge 0.8.0

**Press ⌥M and the next dictation runs on a different engine.** That is the
whole release. Changing engine used to be a five-step trip - open the main
window, open Settings, find the Models pane, pick a row, close it - for a
decision people make constantly and mid-sentence: this recording is Mandarin,
that one is English, this one is worth sending to a provider and the next one is
not. ⌥M is the Models pane's picker without the trip.

## Switch Engine (⌥M)

A press moves to the next ready engine and puts a pill at the top of the screen
naming it - `Engine: Whisper - large-v3-turbo`, `Engine: Parakeet`,
`Engine: Cloud - whisper-1`. The pill sits for two seconds and never takes
focus, because you pressed the key while typing somewhere else and the insertion
point you are about to dictate into must not move.

It is **configurable** like the other three hotkeys, in **Settings →
Shortcuts → Switch Engine**. ⌥M is only the default; it was free alongside ⌥`
(record), ⌥A (Ask) and ⌥S (ask about the screen).

### What a press can land on

Only an engine that could transcribe your *next* dictation, which means both of:

- **Its model is downloaded and can load.** The same check the app already makes
  when it decides what to transcribe with, so "downloaded" means one thing
  everywhere. An engine you have not fetched is not in the cycle, and a press
  never starts a download.
- **It can dictate the language you are dictating.** Paraformer does not refuse
  German - it returns fluent Mandarin for it. The Settings picker is allowed to
  move your dictation language when you choose such an engine, because you are
  looking at the language control while it happens. A key pressed into another
  app must not change two things at once, so that engine is skipped instead.
  **⌥M therefore never changes your dictation language.**

The order is the order the Models picker lists them in, with the cloud engine
last, and it wraps around. With one engine ready a press says so
(`Parakeet is the only engine ready`) rather than doing nothing quietly; with
none it says what is wrong. The shortcut is pressed with no window open, so a
press that reads as a dead key has no other way of explaining itself.

The **cloud engine is offered only when it is already ready to run** - consent
recorded, base URL usable, model named, key stored. A press never gives consent
and never grants one, and on an install that has never turned the cloud path on,
asking the question does not even reach your Keychain.

### A press during a dictation waits

It is **deferred**, not applied and not refused. The words already spoken were
spoken to a particular model and have to be decoded by it, so the pill says
`Engine: … after this dictation` and the switch happens the moment the session
is over. "During a dictation" covers the whole session, including the gap
between the recorder stopping and the transcription starting.

Two smaller rules that you will only notice if they are wrong:

- If the engine you asked for stops being usable while the press waits, the
  press is carried out as though you had made it just now - you asked for a
  working engine, so you get the next one - and the pill names what was actually
  selected. It never names an engine that was not selected.
- **A choice you make in Settings or the Cloud pane while a press is waiting
  wins.** That choice is the newer decision, and applying a pending press over
  it would undo, moments later, something you watched yourself do. The waiting
  press is dropped, and the next press advances from your new choice.

A second press while one is pending advances from the pending engine, so two
presses move two places whether or not a dictation happens to be running.

### It changes nothing else

⌥M writes the same single stored setting the Settings picker writes, through the
same code path, so the shortcut, the picker and the Cloud pane's toggle cannot
drift into meaning three slightly different things. It does not change your
dictation language, your styles, your model downloads or anything about how a
transcript is produced.

The whole story, including why each rule is the way it is:
[docs/engine-shortcut.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/engine-shortcut.md).

## Everything else is unchanged from 0.7.0

- **The cloud path is still opt-in and still off.** Two features can be pointed
  at an OpenAI-compatible provider - speech transcription and the spoken
  "Translate to …" command - and switching either takes an explicit acceptance
  of a sheet naming what is uploaded and where. Style rewriting, the Ask panel
  (⌥A) and screen questions (⌥S) have no cloud path at all, enforced in code.
  A 0.8.0 install you never point at a provider sends nothing, anywhere.
  [docs/cloud-api.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/cloud-api.md).
  If you need "not present" rather than "not enabled",
  `Scripts/build_release.sh --offline-only` still builds exactly that; it is not
  published as a separate download here.
- **The app is still thin.** It ships no model weights. The model you choose is
  fetched on demand and checksummed - SenseVoiceSmall as a verified model pack,
  every other engine by its own downloader - and lands in Application Support,
  where it survives replacing the app.
  [docs/model-packs.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/model-packs.md).
- **EchoForge still never checks for updates on its own.** Checking,
  downloading and installing remain three separate things you press.
- Recordings, personal terms, snippets, styles, shortcuts and downloaded models
  are untouched by this update.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so
macOS will refuse to open it on the first try - typically "the app is damaged
and can't be opened", or "Apple could not verify EchoForge is free of malware".
Nothing is wrong with the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**,
     and click **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

### Expect to grant permissions again

Because these builds are unsigned, macOS treats each one as a **new
application** for privacy purposes. After you replace your copy, it will ask
again for **Microphone** and **Accessibility**, and for **Screen Recording** the
first time you use ⌥S. **This is expected and is not a regression** - it happens
on every unsigned update and will keep happening until these builds are signed
with a Developer ID.

If a stale **EchoForge** entry is already listed under **System Settings →
Privacy & Security → Accessibility**, remove it with the minus button and add
the new app back; macOS otherwise keeps showing the old entry as granted while
the new build has nothing.

The same reason produces one more prompt, and only for people who have stored a
cloud API key: the first time the updated app reads it, macOS asks "EchoForge
wants to use information stored in your keychain". Choose **Always Allow** and
it stops asking. An install that has never turned the cloud path on never reads
the Keychain at all.

Replacing an existing install keeps your recordings, personal terms, snippets,
styles and downloaded models.

Full instructions, including how to use the Chinese engines and the basics of
recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).

## How this build was made

Produced by `Scripts/build_release.sh` and published only after
`Scripts/verify_release_package.sh` checked every embedded library's signature
and `@rpath` dependency and **started the app**.
