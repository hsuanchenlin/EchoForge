# EchoForge 0.3.1

**0.3.0 could not be opened. This release replaces it.** Nothing else has changed - every
feature described in the 0.3.0 notes is here, and this is the build that runs.

## What went wrong

If you downloaded 0.3.0 and macOS answered with a dialog saying EchoForge "cannot be
opened", or that it is not compatible with this version of macOS, nothing was wrong with
your Mac, your download or your installation. Reinstalling the same disk image could not
have fixed it: the app in it could not start on any Mac.

The app ships two libraries of its own inside the bundle - the OpenMP runtime that
whisper.cpp uses, and the text-correction library. 0.3.0 was packaged with macOS's
*hardened runtime* switched on, which tells the system to load only libraries carrying the
same developer Team ID as the app itself. This fork has no Apple Developer ID, so the app
and both libraries were signed ad-hoc, without a Team ID - and macOS refused to load the
app's own libraries into it. It never reached its first line of code.

The signature was valid, which is why this got past the usual check: `codesign --verify
--deep --strict` passed on the published disk image. Only actually starting the app shows
the fault.

## What changed

- **Ad-hoc builds are packaged without hardened runtime**, which is what an unnotarized
  build should have been all along - it buys nothing here and made the app unloadable.
- **There is now one release build path** (`Scripts/build_release.sh`) for both this fork's
  ad-hoc builds and a Developer ID build, instead of a script that only worked with a
  certificate and a hand-assembled release for everyone else.
- **Every release artifact is now verified before it can be published**
  (`Scripts/verify_release_package.sh`): every embedded library is checked for a valid
  signature and a matching Team ID, every `@rpath` dependency is checked to resolve inside
  the bundle, and - the check that would have caught this - **the app is started**.

If you are on 0.2.2, you can skip 0.3.0 entirely and install this.

## Installing this build

This release is **not signed with an Apple Developer ID and not notarized**, so macOS
will refuse to open it on the first try - typically "the app is damaged and can't be
opened", or "Apple could not verify EchoForge is free of malware". Nothing is wrong with
the download; macOS simply cannot check who built it.

1. Open `EchoForge.dmg` and drag `EchoForge.app` into `Applications`.
   Do not run it from the mounted disk image.
2. Then do **one** of the following, once:
   - Right-click (or Control-click) the app in `Applications`, choose **Open**, and click
     **Open** in the dialog; or
   - run `xattr -d com.apple.quarantine /Applications/EchoForge.app` in Terminal
     (adjust the path if you installed it elsewhere).

If you already dragged 0.3.0 into `Applications`, replace it with this one. Your
recordings, personal terms and downloaded models are kept. Because these builds are
unsigned, macOS treats each one as a new app for permission purposes, so it will ask for
Microphone and Accessibility again - and if a stale **EchoForge** entry is already listed
under **Privacy & Security → Accessibility**, remove it with the minus button and add the
new app back.

This build ships with SenseVoice-Small on board, so it is larger than the 0.2.x downloads
and can dictate as soon as it is installed. See the
[0.3.0 notes](v0.3.0.md) for everything that release introduced.

Full instructions, including how to use the Chinese engines and the basics of recording:
[docs/install.md](https://github.com/hsuanchenlin/EchoForge/blob/master/docs/install.md).
